#### Day 2 (Tuesday)：CSS盒模型与Flexbox导航

**晨会概念清单**
| 概念（中） | 概念（英） | 释义 |
|:---|:---|:---|
| 层叠样式表 | CSS | 控制网页的样式和布局 |
| 盒模型 | Box Model | 每个元素由 content + padding + border + margin 组成 |
| 弹性盒子 | Flexbox | 一维布局模型，用于排成一行或一列 |
| 选择器 | Selector | 选中要应用样式的元素，如 `.class`、`#id` |

**Guided Practice**：制作响应式导航栏
```css
/* style.css */
* { margin: 0; padding: 0; box-sizing: border-box; }

nav {
  display: flex;
  justify-content: space-between;  /* 两端对齐 */
  align-items: center;             /* 垂直居中 */
  padding: 1rem 2rem;
  background: #333;
  color: white;
}

.nav-links {
  display: flex;
  gap: 2rem;   /* 子元素间距 */
  list-style: none;
}

/* 移动端适配 */
@media (max-width: 768px) {
  nav { flex-direction: column; gap: 1rem; }
  .nav-links { flex-direction: column; align-items: center; }
}
```

**PM视角**
> **问题**：移动端适配为什么重要？
> **回答**：全球超60%的网页流量来自移动设备。如果导航在手机上显示不全或难以点击，你将直接流失大部分潜在用户。
> **PM决策**：**Mobile-First（移动优先）** 设计策略——先设计手机版，再扩展到大屏，确保核心用户体验覆盖最大用户群。

**独立项目**：将作品集的导航改为Flexbox布局，实现PC端水平、移动端垂直折叠的效果。Git commit：`"feat: 实现响应式Flexbox导航"`

**Guided Practice**：Todo List 核心逻辑
```javascript
const input = document.getElementById('todoInput');
const addBtn = document.getElementById('addBtn');
const list = document.getElementById('todoList');
```

#### Day 8 (Wednesday)：异步编程（Async/Await + Fetch）

**晨会概念**
| 概念（中） | 概念（英） | 释义 |
|:---|:---|:---|
| 异步 | Asynchronous | 不阻塞后续代码执行，等结果回来再处理 |
| 承诺 | Promise | 代表未来完成的异步操作 |
| 异步函数 | Async Function | `async function` 声明 |
| 等待 | Await | 等待Promise完成 |

**Guided Practice**：从API获取名言并显示
```javascript
async function fetchQuote() {
  const loading = document.getElementById('loading');
  const quoteDiv = document.getElementById('quote');
  
  loading.style.display = 'block';
  try {
    const res = await fetch('https://api.quotable.io/random');
    if (!res.ok) throw new Error(`HTTP error! status: ${res.status}`);
    const data = await res.json();
    quoteDiv.textContent = `"${data.content}" —— ${data.author}`;
  } catch (error) {
    quoteDiv.textContent = '加载失败，请稍后重试';
    console.error('Fetch error:', error);
  } finally {
    loading.style.display = 'none';
  }
}
```

**PM视角**
> **问题**：为什么要有 `loading` 和 `catch`？
> **回答**：
> - **Loading**：用户等待时看到加载状态，知道“系统正在工作”，避免焦虑流失。
> - **Error Handling**：网络不稳定是常态，产品必须优雅降级，而不是直接崩溃或白屏。
> **PM金句**：**“好的产品，在出错时也不会让用户感到无助。”**

#### Day 12 (Tuesday)：State与Hooks

**Guided Practice**：计数器 + 待办列表（React版）
```tsx
import { useState } from 'react';

function TodoApp() {
  const [todos, setTodos] = useState<{ id: number; text: string; done: boolean }[]>([]);
  const [input, setInput] = useState('');

  const addTodo = () => {
    if (!input.trim()) return;
    setTodos([...todos, { id: Date.now(), text: input, done: false }]);
    setInput('');
  };

  const toggleTodo = (id: number) => {
    setTodos(todos.map(t => t.id === id ? { ...t, done: !t.done } : t));
  };

  return (
    <div>
      <input value={input} onChange={(e) => setInput(e.target.value)} />
      <button onClick={addTodo}>添加</button>
      <ul>
        {todos.map(t => (
          <li key={t.id} onClick={() => toggleTodo(t.id)} style={{ textDecoration: t.done ? 'line-through' : 'none' }}>
            {t.text}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

**PM视角**
> **问题**：为什么用 `[...todos, newTodo]` 而不是 `todos.push(newTodo)`？
> **回答**：**不可变数据（Immutable Data）**。直接修改数组不会触发React重新渲染。用展开运算符创建新数组，React才能检测到变化并更新UI。这是React的**核心设计哲学**。


**PM视角**
> **问题**：路由（Routing）对产品意味着什么？
> **回答**：路由是产品的**信息架构**。清晰、可分享的URL（如 `/product/123`）让用户能收藏、分享特定页面，也便于搜索引擎抓取。**每个页面都应有唯一的URL**。

## 七、评估体系（PM视角版）

| 维度 | 权重 | 评分标准 |
|:---|:---:|:---|
| **技术实现** | 60% | 代码是否能运行？是否按规范完成所有功能？ |
| **用户体验** | 20% | 交互是否流畅？错误提示是否友好？是否适配移动端？ |
| **产品思维** | 10% | 功能设计是否合理？是否覆盖用户真实场景？ |
| **工程规范** | 10% | Git提交是否清晰？代码是否可读？有无注释？ |

**每周交付物检查清单**：
- [ ] GitHub仓库（公开，README完善）
- [ ] 至少N次有意义的Git提交
- [ ] 项目在本地浏览器正常运行
- [ ] 无 `console.log` 调试残留
- [ ] 讲师Code Review通过
